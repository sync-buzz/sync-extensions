# Issues

What is open on a public GitHub repository, read in the window beside the
project it is about. It publishes no kinds and offers you nothing to call: the
section fetches from GitHub as a person looks at it, and nothing it shows is
stored in this project's memory.

That is the useful thing to know. **An issue is not a record here.** If
something on that tracker matters to this project — it explains a constraint,
it is the reason for a piece of work, it is where a decision was argued out —
write the record that holds that claim in this project's own words, and point
at the issue by its URL from inside it. What you must not do is describe the
tracker's contents as though the project had recorded them: nothing here is
reconciled against anything, an issue closes without this memory hearing about
it, and a record that quietly went out of date on somebody else's repository is
worse than no record.

Read the tracker yourself when you need it, with whatever you use to reach
GitHub. This section is for the person at the window.
